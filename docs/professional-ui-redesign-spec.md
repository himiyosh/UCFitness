# UCFitness プロフェッショナル UI リデザイン設計書

> **目的**: 現在の「個人制作感」「装飾過多」「情報階層の弱さ」を解消し、Fitbit 連携の信頼性、日次習慣化、グループ競争、UC 報酬を大手プロダクト品質で伝えるための UI/UX 再設計方針を定義する。
>
> **対象**: ランディング、ホーム、ランキング、グループ、チャレンジ、ウォレット、ショップ、プロフィール、オンボーディング。
>
> **前提**: Next.js 15 / React 18.3 / Tailwind CSS v4 / CSS カスタムプロパティを継続使用。新規外部 UI ライブラリは追加しない。

---

## 1. 結論

UCFitness の認証済み画面は **「ポップな歩数ゲーム」から「信頼感のあるフィットネス習慣化プラットフォーム」へ**寄せるべきです。一方、公開ランディングページはブランド面として、歩く・競う・報われる熱量を明るい意味色で明示します。

現状の主な課題は、機能不足ではなく **表現の統制不足** です。グラデーション、絵文字、ガラスカード、多数テーマ、アニメーションがそれぞれ単体では楽しい一方、全体として「何が一番重要か」「本当に健康データを預けてよいか」が伝わりにくくなっています。

リデザインの最優先は以下です。

1. **ホームを「今日の行動判断画面」に作り替える**
2. **色・余白・角丸・影・文字サイズをプロ品質のトークンに統一する**
3. **絵文字と派手な装飾を原則撤廃し、達成演出だけに限定する**
4. **ランキングは順位表ではなく「あと何歩で上がれるか」を中心に再設計する**
5. **UC はゲーム内コインではなく、努力が積み上がる成果として見せる**
6. **初回体験を「Fitbit 連携 → 目標設定 → 最初のチャレンジ」の 3 ステップに絞る**

### 1.1 公開ランディングページの例外

認証済みアプリ画面はニュートラル基調の Product register、公開 LP は Full Palette の Brand register として扱います。公開 LP の抑制しすぎは、サービス固有の楽しさ・競争・報酬を消し、汎用的な暗色 SaaS に見せるため禁止します。

- 明るい背景と自然高さを基本にし、`min-h-screen` + `flex-1` で空白を引き伸ばさない。
- 青=目標・主 CTA、緑=達成・同期、紫=競争・順位、アンバー=UC・報酬として使い分ける。
- 375px でも歩数リング、順位差、UC、チャレンジの実 UI を表示する。モバイルだけプレビューを隠さない。
- 暗色全面ヒーロー、青紫のぼかし中心の SaaS 表現、グラデーション文字、装飾目的の全面 glassmorphism は使わない。
- ファーストビューで主要 CTA と、歩数進捗・順位差・報酬・チャレンジのうち最低 2 つを認識できること。

## 2. 参考調査サマリー

### 2.1 競合・参考サービスからの学び

| サービス | 観察した特徴 | UCFitness への示唆 |
|---|---|---|
| Fitbit / Google Health | 健康コーチング、デバイス比較、Google らしい余白と信頼感。健康データを扱う安心感が強い | Fitbit 連携・同期状態・データ信頼性を UI 上で明確に扱う |
| Strava | 「Community-Powered Motivation」。活動を投稿・応援・比較の対象として扱い、分析・共有・探索/競争を分けている | グループやランキングは単なる表ではなく「仲間も動いている」感を出す |
| Nike Run Club | コーチング、チャレンジ、達成祝い、伴走感。数字だけでなく「一緒に走る」トーンが強い | マイクロコピーは命令ではなく伴走型にする。達成演出は上品に記憶へ残す |
| Sweatcoin | 歩く→報酬、バッジ、ストリーク、マーケットプレイス、友人競争が明快 | UC の価値と次の報酬条件を見える化し、歩く理由を明確にする |
| MyFitnessPal | 「1-2-3」のステップ型オンボーディング、実績・レビュー、連携数による信頼感 | 初回説明は 3 ステップに圧縮し、利用開始の心理的負荷を下げる |
| WHOOP | 黒基調のプレミアム感、24/7 insights、回復・負荷・睡眠など指標統合、著名人/証言による信頼 | プレミアム感は装飾ではなく、余白・写真・数値カード・洞察で作る |

### 2.2 デザイン知見からの要件

| 知見 | 適用方針 |
|---|---|
| Aesthetic-Usability Effect | 見た目の洗練度は「使いやすそう」「信頼できそう」に直結する。派手さより一貫性を優先 |
| Goal-Gradient Effect | 目標に近いほど行動意欲が上がる。残り歩数・残り時間換算・順位差を常時見せる |
| Hick's Law | 選択肢が多いほど迷う。ホームのファーストビューで主要アクションは最大 2 つ |
| Fitts's Law | モバイルでは大きく近いタップ領域が重要。主要 CTA は 44px 以上、下部ナビは最大 5 項目 |
| Common Region / Proximity | 関連情報はカードや背景でまとめ、無関係な情報は余白で分ける |
| Peak-End Rule | 達成時とセッション終了時の印象が継続意欲を左右する。達成カード・週次振り返りを強化 |
| Refactoring UI | ボーダーを減らし、太さ・色・余白で階層化する。画面を無理に埋めない |

### 2.3 Modern Web Guidance からの要件

- **アクセシビリティ**: セマンティック HTML、見えるフォーカス、キーボード操作、十分なコントラスト、状態を色だけで伝えない。
- **CSS / レイアウト**: 固定幅ではなく intrinsic sizing、`min-width: 0`、レスポンシブ grid/flex、長文折り返しを前提にする。
- **重いコンテンツ**: ファーストビュー外の長いリストや重いカード群に限定して `content-visibility: auto` を検討する。ホーム上部や検索対象コンテンツには安易に使わない。
- **モーション**: 方向性のある遷移は有効だが、Baseline 2024 方針では View Transitions 依存にしない。CSS transition を基本にし、必要時のみ機能検出する。

## 3. 現状 UI の問題分析

### 3.1 「素人感」の主因

| 原因 | 現状の兆候 | 改善方向 |
|---|---|---|
| 色が多い | `--accent-coral`, `--accent-turquoise`, `--accent-lime`, 多数テーマ、派手なグラデーション | ニュートラル基調 + 1 ブランドカラー + セマンティックカラーに整理 |
| 絵文字依存 | ランディング背景、ナビ、カード、達成表現で絵文字が多い | ナビ・見出し・通常カードから絵文字を撤廃。達成演出だけに限定 |
| ガラス表現過多 | `glass-card`, `backdrop-blur`, 半透明背景が多数 | 基本は不透明 surface。ガラスはヘッダー/特別演出のみ |
| カード過多 | すべてが角丸・影付きカードになり、重要度差が弱い | Hero だけ強く、補助情報はリスト/薄い surface/余白で整理 |
| 情報階層が弱い | 歩数、ランキング、チャレンジ、UC、ギアが同じ重さで並ぶ | 「今日の歩数」→「次アクション」→「競争/報酬」の順に階層化 |
| テーマ乱立 | Classic, Pop, Midnight, Sakura, Ocean, Forest, Sunset, Cyberpunk, Galaxy | ブランド品質優先なら Light / Dark / System へ縮小。特別テーマはイベント/報酬として限定 |
| 常時アニメーション | 背景の浮遊絵文字、虹アニメーション、バウンド表現 | 常時動く装飾を停止。進捗・達成・タップ反応だけに使う |

### 3.2 残すべき強み

- Fitbit 連携という明確な健康データ基盤
- グループ・ランキング・チャレンジ・UC の習慣化ループ
- PWA とモバイルファーストの方向性
- CSS カスタムプロパティによるテーマ基盤
- ランキング行・リアクションなど、既に細かく保護された仕様

### 3.3 捨てるべき表現

- ページ全体の派手な背景グラデーション
- ナビゲーションや見出しの絵文字
- すべてのカードに影・ボーダー・半透明を重ねる表現
- 常時動く背景装飾
- 多すぎるテーマをプロダクトの中心体験に置くこと
- 「コイン」「ギア」を健康成果より前面に出す順序

## 4. ブランドポジショニング

### 4.1 推奨コンセプト

**毎日の歩数を、続けたくなる成果に変えるフィットネス習慣化アプリ**

または短く:

**歩く、競う、続く。Fitbit 連携の習慣化フィットネス。**

### 4.2 狙うポジション

```text
健康データの信頼感  +  コミュニティ競争  +  報酬による継続
Fitbit / WHOOP      Strava / Nike        Sweatcoin
```

UCFitness は、医療・高級ウェルネスに寄りすぎず、ゲームにも寄りすぎない **「信頼できる日次モチベーション基盤」** を目指すべきです。

### 4.3 目指す印象

| 項目 | 方針 |
|---|---|
| 信頼感 | Fitbit 連携、最終同期、歩数反映状態を隠さない |
| 習慣化 | 今日の残り歩数、ストリーク、週次進捗を中心にする |
| 競争 | 自分の順位、次の順位までの差、グループの動きを見せる |
| 報酬 | UC を努力の証として扱い、履歴と条件を透明化する |
| プロ感 | 絵文字ではなくタイポグラフィ、余白、写真/アイコン、構造で見せる |

## 5. デザイン原則

### 5.1 UI の人格

| 軸 | 現状 | 目標 |
|---|---|---|
| トーン | ポップ、ゲーム風 | 静かな自信、継続を支える伴走感 |
| 色 | 多色、グラデーション中心 | ニュートラル + ブランドカラー + 状態色 |
| 情報 | たくさん見せる | 今必要な判断だけを上に出す |
| 報酬 | コイン/ギアが遊びっぽい | 努力の蓄積として信頼感を持たせる |
| モーション | 楽しさのために動かす | 状態変化と達成のためだけに動かす |

### 5.2 カラー

#### 推奨トークン

既存の `--theme-*` は互換性のため残しつつ、新しい意味ベースの `--color-*` を上位契約として追加します。

```css
:root {
  --color-bg: #F6F7F9;
  --color-surface: #FFFFFF;
  --color-surface-muted: #EEF1F5;
  --color-text: #111827;
  --color-text-muted: #5B6472;
  --color-border: #DDE3EA;

  --color-primary: #2563EB;
  --color-primary-strong: #1D4ED8;
  --color-primary-soft: #DBEAFE;
  --color-primary-solid: #1D4ED8;
  --color-success: #16A34A;
  --color-success-strong: #166534;
  --color-success-soft: #DCFCE7;
  --color-warning: #D97706;
  --color-danger: #DC2626;
  --color-reward: #B7791F;
  --color-reward-strong: #92400E;
  --color-reward-soft: #FEF3C7;
  --color-competition: #7C3AED;
  --color-competition-strong: #5B21B6;
  --color-competition-soft: #EDE9FE;
  --color-competition-solid: #6D28D9;
  --color-play: #E11D48;
  --color-play-soft: #FFE4E6;
  --color-inverse-surface: #0F172A;
  --color-inverse-text: #FFFFFF;
}
```

#### 使用ルール

- `--color-primary` はアクセント文字、選択状態、重要な進捗だけ。
- 淡い主色面の文字には `--color-primary-strong`、白文字を載せる塗り面には `--color-primary-solid` を使う。
- 白文字を載せる塗り CTA には `--color-primary-solid` を使う。
- 濃色ヒーローやプロダクトモックには `--color-inverse-surface` / `--color-inverse-text` を使い、`--color-text` を背景色として流用しない。
- Success は達成、同期成功、ストリーク継続。
- Competition は順位、対戦、グループ競争。
- Competitionの白文字付き塗り面には `--color-competition-solid` を使う。
- Warning は期限間近、あと少し、注意。
- Danger は失敗、削除、重大エラー。
- Reward は UC、報酬、バッジに限定。
- Play は公開 LP の最終 CTA や限定的な楽しさの表現に使用し、エラー色と混同しない。
- 背景グラデーションは原則廃止。公開 LP も単色の意味面を組み合わせ、文字へのグラデーションは使わない。

### 5.3 タイポグラフィ

数字を主役にします。大手品質のダッシュボードでは、装飾よりも **数字の読みやすさと差分の理解** が信頼感を作ります。

| 用途 | モバイル | デスクトップ | 方針 |
|---|---|---|---|
| 今日の歩数 | `text-5xl` | `text-6xl` | 画面内で最も強い |
| ページ見出し | `text-2xl` | `text-3xl` | 太すぎず `font-semibold` 基本 |
| セクション見出し | `text-base` | `text-lg` | カードの主題 |
| 本文 | `text-sm` | `text-base` | 14px 未満にしない |
| 補足 | `text-xs` | `text-sm` | コントラスト 4.5:1 を維持 |
| 数値 | `tabular-nums` | `tabular-nums` | 桁揃えで信頼感を出す |

### 5.4 余白・密度

| 要素 | 推奨 |
|---|---|
| 画面左右余白 | 16px、`sm:` 以上 24px |
| ファーストビュー内カード間 | 12px |
| セクション間 | 24px〜40px |
| カード内余白 | 16px、重要カードのみ 20px〜24px |
| リスト行 | 12px〜16px |
| 最大幅 | 通常 `max-w-7xl`、テキスト中心 `max-w-prose` |

画面を埋め切らないことを原則にします。余白は「未完成」ではなく、情報の優先順位を伝えるための要素です。

#### ナビゲーション幅の統一

ランディング、認証後ホーム、各ページの top header / page content / footer は、必ず同じ内側幅を共有します。

```tsx
<div className="mx-auto max-w-7xl w-full px-4 sm:px-6 lg:px-8">
  ...
</div>
```

サイドバー付きのデスクトップアプリシェルでも、sticky header の中身を `w-full px-*` のまま全幅配置しません。メインコンテンツと同じ `mx-auto max-w-7xl w-full px-4 lg:px-6 xl:px-8` に入れ、ヘッダー右端・本文カード右端・フッター右端を揃えます。

検証基準:

- 1280px / 1920px で header 内側・最初の section・footer の left/right が一致する。
- 375px で top header と本文の左右余白が 16px 基準で揃う。
- 例外はモバイル固定ボトムナビのみ。ボトムナビは `left: 0; right: 0` で画面幅を使い、内部項目だけ `max-w-lg` 等で制約してよい。

### 5.5 カード・面・影

| 種別 | 用途 | 見た目 |
|---|---|---|
| Hero Surface | 今日の歩数、最重要状態 | 強い面、薄い影、明確な余白 |
| Metric Tile | ランキング、UC、ストリーク | 小さな面、影なし、背景差 |
| List Row | ランキング、履歴、メンバー | カード化せず行として表示 |
| Action Panel | 次アクション、同期エラー | 強めの色付き面、CTA 明確 |
| Celebration Card | 達成、バッジ獲得 | 一時的な強調。常時表示しない |

カードの全使用箇所に影を付けるのは禁止します。階層は **面の強さ、余白、文字の太さ** で作ります。

### 5.6 アイコン・絵文字

- 通常 UI の見出し・ナビ・カードタイトルから絵文字を撤廃する。
- 状態アイコンは SVG または既存のシンプルな図形に統一する。
- 絵文字を許可するのは、達成祝い、ストリーク節目、バッジ獲得など一時的な感情表現のみ。
- 色だけで状態を伝えず、必ずラベルや数値を併用する。

### 5.7 モーション

| 許可 | 禁止 |
|---|---|
| 進捗バーの伸長 | 常時浮遊する背景絵文字 |
| タップ時の 0.97 scale | 無限バウンド |
| 達成カードの軽い fade/slide | 過剰な紙吹雪 |
| タブ切替の 150〜200ms transition | 複数 animation の同一要素適用 |
| スケルトンの控えめ pulse | 視線を奪う装飾アニメーション |

`prefers-reduced-motion` は必ず尊重します。

## 6. ユーザージャーニー設計

### 6.1 中核 JTBD

> 今日の歩数や目標との差を確認したいとき、現在の進捗・順位・報酬をすばやく把握して、あと少し歩くかどうかを判断したい。

### 6.2 毎日の利用フロー

| 段階 | ユーザーの問い | UI が返すべき答え |
|---|---|---|
| 起動 | 今日どれくらい歩いた？ | 今日の歩数、達成率、最終同期 |
| 判断 | あとどれくらい？ | 残り歩数、推定所要時間、目標までの距離 |
| 比較 | 競争ではどう？ | 自分の順位、次の順位までの差、グループの動き |
| 行動 | 何をすればいい？ | 歩く、同期する、チャレンジ参加、グループ確認 |
| 達成 | 続けてよかった？ | UC獲得、ストリーク、バッジ、明日の提案 |

### 6.3 初回オンボーディング

MyFitnessPal のように、開始体験は 3 ステップへ圧縮します。

```text
1. Fitbit と連携
2. 目標歩数を設定
3. グループまたはチャレンジに参加
```

初回で説明しないもの:

- ショップ詳細
- すべてのテーマ
- 全ランキング種別
- 高度な分析
- ギア装備の細部

## 7. 情報設計

### 7.1 ナビゲーション再編

モバイル下部ナビは最大 5 項目にします。

推奨:

```text
ホーム / ランキング / チャレンジ / グループ / マイページ
```

UC とショップは「マイページ」またはホーム内の報酬カードから遷移させます。報酬を下部ナビに独立させる案もありますが、初回利用者には「健康アプリ」より「ポイントアプリ」に見えやすいため、第一段階では避けます。

### 7.2 ホームの情報階層

```text
Lv1: 今日の歩数
Lv2: 目標までの差 / 達成率 / 同期状態
Lv3: 次アクション / 順位アップまでの差
Lv4: ランキング / チャレンジ / UC / ストリーク
Lv5: 活動履歴 / おすすめ / ギア / 補足
```

### 7.3 画面別の最重要情報

| 画面 | 最重要情報 | 削るべき情報 |
|---|---|---|
| ランディング | Fitbit 連携で何ができるか、信頼性、開始 CTA | 浮遊絵文字、過剰な抽象コピー |
| ホーム | 今日の歩数、残り歩数、同期状態、次アクション | 同じ強さのカード羅列 |
| ランキング | 自分の順位、次の順位までの差、Top 3 | 全員を同じ強さで並べること |
| グループ | 所属グループの動き、今週の合計、アクティブメンバー | 装飾バナーの優先表示 |
| チャレンジ | 参加中、残り期間、進捗、報酬 | おすすめの出しすぎ |
| ウォレット | 残高、今日/今週の獲得、次の獲得条件、履歴 | 派手なコイン演出 |
| ショップ | 使う理由、装備効果、人気/おすすめ | 商品カードの情報過多 |
| プロフィール | 実績、ストリーク、公開情報、装備 | テーマや装飾の過剰な前面化 |

## 8. 主要画面設計

### 8.1 ランディング

#### 目的

未ログインユーザーに「これは健康データを預けられる本格的なサービス」と感じてもらい、Fitbit ログインへ進ませる。

#### 推奨構成

```text
[Header]
UCFitness / 言語 / Fitbitで始める

[Hero]
Fitbitの歩数を、続く習慣と成果へ。
今日の歩数・ランキング・UC報酬をひとつに。
CTA: Fitbitで始める
Sub: 30秒で連携、歩数は自動同期

[Product Preview]
スマホ画面モック: 今日の歩数、残り歩数、順位差

[3 Benefits]
続く: 目標までの差がすぐ分かる
競う: グループとランキングで続く
報われる: 歩いた分がUCとして積み上がる

[Trust]
Fitbit連携 / PWA / プライバシー配慮 / 日本語対応
```

#### 変更方針

- 背景の浮遊絵文字を撤廃。
- 3 枚の機能カードは小さくし、スマホモックを主役にする。
- グラデーション文字はブランドロゴか CTA 周辺に限定。
- CTA ボタンは 1 つを強く、補助リンクは弱く。

### 8.2 ホーム

#### 目的

起動から 3 秒で「今日どうするか」を判断できる画面にする。

#### 推奨構成

```text
[Top Bar]
挨拶 / 最終同期 / 通知 / プロフィール

[Today Command Center]
今日の歩数 7,820
目標まであと 2,180 歩
78% progress
同期: 5分前

[Action Insight]
あと約18分のウォーキングで達成
11位まであと1,240歩

[4 Summary Tiles]
ランキング / チャレンジ / UC / ストリーク

[Community Momentum]
グループの最近の活動

[Detailed Sections]
ミッション / チャレンジ / フォロー / おすすめ
```

#### 注意

- ファーストビューの数字は最大 4 個。
- ヒーロー内の背景グラデーションは廃止または非常に控えめにする。
- 「同期」ボタンを単なるアイコンではなく、状態付きにする。

### 8.3 ランキング

#### 目的

順位表を見る画面ではなく、「もう少し歩けば上がれる」と理解する画面にする。

#### 推奨構成

```text
[Period Switch]
今日 / 今週 / 今月

[My Rank]
現在 12位
11位まであと 1,320 歩
上位 28%

[Top 3]
大きく、でもランキング行仕様は維持

[Around Me]
1つ上 / 自分 / 1つ下

[Group Ranking]
所属グループ別
```

#### 既存仕様の維持

ランキング行の既存保護仕様は変更しません。

- `min-h-[4.5rem]`
- 最低 5 行表示
- `transition-colors` のみ
- リアクションピッカー Portal 仕様

### 8.4 グループ

#### 目的

「仲間がいるから続く」を感じる画面にする。

#### 推奨構成

```text
[Group Overview]
今週の合計歩数 / アクティブメンバー / 自分の貢献

[Group Momentum]
今日歩いたメンバー
順位変動
最近のリアクション

[Group Challenge]
参加中 / 募集中

[Member List]
上位 / 自分周辺 / 最近アクティブ
```

#### 変更方針

- バナー画像はデスクトップ中心。モバイルではコンパクトな情報カードを優先。
- グループカードは「写真カード」より「活動量カード」にする。
- 招待・作成 CTA は画面下部に逃がさず、空状態で明確に出す。

### 8.5 チャレンジ

#### 目的

短期目標で日次習慣を補助する。

#### 推奨構成

```text
[Active Challenge]
残り日数 / 現在進捗 / 報酬 / 次に必要な歩数

[Recommended 3]
初心者向け / 短期集中 / グループ型

[Completed]
達成履歴
```

#### 変更方針

- おすすめは最大 3 件。
- 達成条件をタイトルより上に出す。
- 「参加者数」より「あなたが次にやること」を優先。

### 8.6 ウォレット / UC

#### 目的

報酬の信頼性と積み上がりを伝える。

#### 推奨構成

```text
[Balance]
現在のUC
今週獲得

[Next Reward]
あと 1,200 歩で +12 UC

[History]
歩数 / ミッション / チャレンジ / 購入

[Use UC]
ショップ / ギア / シールド
```

#### 変更方針

- コイン演出より明細の透明性を優先。
- UC の増減理由を明確にする。
- 報酬計算が分からない状態を避ける。

## 9. コンポーネント刷新方針

### 9.1 App Shell

- モバイル: 下部ナビ 5 項目、上部は軽量な状態バー。
- デスクトップ: サイドバーは 240〜280px、現在地と主要 CTA のみ。
- 背景は `--color-bg` の単色または非常に薄いニュートラル。

### 9.2 Today Command Center

ホームの主役コンポーネントです。

必須要素:

- 今日の歩数
- 目標までの残り歩数
- 達成率
- 最終同期
- 状況別メッセージ
- 主要 CTA

状態別コピー:

| 状態 | コピー例 |
|---|---|
| 0〜49% | まずは10分歩いて、今日の流れを作りましょう |
| 50〜79% | もう少しで後半戦。午後の散歩で届きそうです |
| 80〜99% | あと少しで達成です |
| 100%〜 | 今日の目標を達成しました。明日の自分にもつなげましょう |

### 9.3 Metric Tile

小さな指標カードは以下で統一します。

```text
[ラベル]
[大きな数値]
[差分または補足]
```

禁止:

- 絵文字をラベル代わりにする
- グラデーション背景を毎回使う
- 補足情報を 2 行以上詰め込む

### 9.4 List Row

ランキング、履歴、メンバー、活動ログはカードではなくリストとして扱います。

行の原則:

- 左: 主体
- 中央: 補足
- 右: 数値 / 状態
- 行高は一定
- アイコンは最小限

### 9.5 Empty / Error / Loading

大手品質では、空状態とエラー状態も「体験」です。

| 状態 | 方針 |
|---|---|
| Loading | 骨組みが実画面と一致するスケルトン |
| Empty | 次の行動を 1 つだけ提示 |
| Error | 原因を短く、解決手段を明確に |
| Sync Error | Fitbit 再同期や権限確認へ誘導 |

## 12. 品質基準

### 12.1 見た目

- 画面全体で使う主要色は 1 つ、状態色は意味ごとに固定。
- ファーストビューに表示する主要数値は 4 個以内。
- 通常画面の絵文字はゼロを目標にする。
- カードの影は最大 2 段階。
- `border`, `shadow`, `backdrop-blur` を同時に多用しない。

### 12.2 モバイル

- 375px で横スクロールなし。
- 主要ボタンは 44px 以上。
- 下部ナビは最大 5 項目。
- 1 画面目で「今日の状態」と「次アクション」が分かる。
- 固定高さ + `overflow-hidden` でページ全体を閉じ込めない。

### 12.3 アクセシビリティ

- 通常テキスト 4.5:1 以上。
- フォーカスリング 3:1 以上。
- 色だけで達成・警告・順位を伝えない。
- カスタムタブ、メニュー、ダイアログはキーボード操作可能。
- `prefers-reduced-motion` と `forced-colors` を壊さない。

### 12.4 パフォーマンス

- ファーストビューの LCP 候補を遅延ロードしない。
- 下部の長いリストには必要に応じて `content-visibility: auto` を検討。
- 常時アニメーションを削減。
- Recharts など重いコンポーネントは既存方針どおり遅延読み込み。
- 画像はサイズ指定と `sizes` を明示。

## 13. やらないこと

- 新しい UI ライブラリの追加。
- `framer-motion` の導入。
- 絵文字やグラデーションを増やして「楽しい風」にすること。
- 多数テーマをさらに増やすこと。
- ランキング行の保護仕様を崩すこと。
- 主要パネルを `<details>` で隠すこと。
- モバイルで root スクロールを止めること。
- 健康データよりコインやショップを上位に置くこと。

## 17. 殺風景化フィードバック対応設計

### 17.1 問題の再定義

第一段階のリデザインでは、絵文字・過剰グラデーション・常時アニメーションを削減したことで素人感は下がりました。一方で、UCFitness の核である **歩く楽しさ、競争、報酬、コミュニティの熱量** まで弱まり、白いカード中心の汎用 SaaS 風 UI になりました。

今後は「静かな信頼感」だけではなく、**プロ品質のフィットネスプロダクトらしい熱量** を戻します。

### 17.2 新しいバランス

| 軸 | 避ける状態 | 目標 |
|---|---|---|
| 装飾 | 絵文字・虹色・浮遊演出でにぎやかに見せる | 色面、進捗リング、実UI風モック、重なりで見せる |
| シンプルさ | 白背景と白カードだけで情報が薄い | 重要セクションごとに面の強さを変える |
| ゲーム感 | コインやバッジを子どもっぽく見せる | 順位差、UC、チャレンジを数値カードで見せる |
| プロ感 | 無難なB2B SaaS風に寄りすぎる | Strava / Fitbit / Sweatcoin の中間に置く |
| モーション | 常時動く装飾で視線を奪う | 進捗・状態変化・達成時のみ軽く動く |

### 17.3 ビジュアルレイヤー

プロ品質とワクワク感を両立するため、以下の 5 レイヤーを使います。

1. **Brand field**: Hero と CTA だけに大きなグラデーション面を使い、ブランドの記憶を作る。
2. **Product mock**: 実際のホーム体験を想像できるスマホモックを主役にする。
3. **Progress objects**: 歩数リング、進捗バー、順位差カードを使い、達成までの距離を視覚化する。
4. **Social proof**: ユーザー数、記録歩数、チャレンジ数などでサービスの厚みを出す。
5. **Habit loop**: Sync → Move → Compete → Reward の流れを明示し、アプリを開く理由を作る。

### 17.4 実装方針

#### ランディング

- Hero 背景に控えめだが大きいブランドグラデーションを配置。
- スマホモックを「黒いプロダクト面 + 歩数リング + チャレンジカード」に刷新。
- 「順位アップ」「次の報酬」などの浮遊カードを追加し、機能の期待値を上げる。
- Stats を白カードではなく濃色バーにし、画面に締まりを作る。
- Habit loop セクションを追加し、Fitbit 連携後の利用イメージを説明する。
- 最終 CTA を追加し、スクロール後にも開始導線を残す。

#### ホーム

- Today Command Center は白カードではなく、濃色の主役面にする。
- 今日の歩数を最大の数字として表示し、右側に進捗リングを置く。
- 次アクションカードは白い面で浮かせ、CTA を明確にする。
- 同期状態・順位差は濃色面上の小さな glass tile として扱う。

### 17.5 ガードレール

- 絵文字は通常 UI には戻さない。
- グラデーションは Hero / CTA / 重要なプロダクト面に限定する。
- 常時アニメーションは追加しない。点滅・浮遊・無限バウンドは禁止。
- 375px では情報を縦に積み、横スクロールを出さない。
- ランキング行の保護仕様は変更しない。
- デスクトップの root 0.9x transform スケーリングや `html { overflow-y: hidden }` でページスクロールを殺さない。
- 認証済みページのデスクトップ左ナビは `app/[locale]/layout.tsx` の共通 App Shell に集約し、ページごとに表示/非表示をばらつかせない。
- 主要画面のファーストビューはモノクロだけで構成しない。ブランド色面、進捗、順位差分、報酬、チャレンジのうち最低 2 要素を入れる。

### 17.6 今回の実装スコープ

| 対象 | 変更 |
|---|---|
| `LandingPage.tsx` | Hero、Product Preview、Stats、Habit loop、Showcase、Final CTA を強化 |
| `HomeHero.tsx` | Today Command Center を濃色・進捗リング・CTA 付きに刷新 |
| `messages/ja.json`, `messages/en.json` | 追加セクションと CTA 文言を ja/en 両方で追加 |

### 17.7 フィードバック反映ルール

ユーザーから UI 品質・設計運用・エージェントルールに対する指摘があった場合は、実装修正だけで終わらせません。

必須対応:

1. 反省点を明文化する。
2. 根本原因を特定する。
3. `.github/copilot-instructions.md` または該当 instruction/skill に再発防止ルールを追加する。
4. 実装を修正する。
5. 追加したルールに対応する検証を実行する。

今回の再発防止:

- ナビ幅一致を 1280px / 1920px で `getBoundingClientRect().left/right` 検証する。
- デスクトップの左サイドバーは共通 App Shell で表示する。
- root スクロールロックと 0.9x transform スケーリングを禁止する。
- 「殺風景化禁止」として、主要ファーストビューに色面・進捗・競争・報酬の視覚要素を最低 2 つ入れる。
