## 2025-02-28 - Supabase 500 Error on Invalid UUID Input
**Vulnerability:** API endpoints that legitimately accept user IDs via query parameters (e.g., `targetUserId` in `/api/user/follow/status`, `userId` in `/api/user/achievement-progress` and `/api/user/step-calendar`) pass these directly to Supabase queries without UUID validation. Supabase (PostgreSQL) throws an unhandled 500 Internal Server Error exception if an improperly formatted string is passed into a query expecting a UUID type.
**Learning:** In a codebase using PostgREST/Supabase, relying on the database client to fail on type mismatches can cause unhandled 500 errors. We must explicitly validate parameter formats (especially UUIDs) *before* executing the query to ensure we return a graceful 400 Bad Request error instead of crashing or leaking server error states.
**Prevention:** Always validate and sanitize UUID inputs (e.g., using `isValidUUID` from `@/lib/validation`) from request query parameters before passing them to the database client.
