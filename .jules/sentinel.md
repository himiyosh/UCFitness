## 2025-05-09 - [Missing UUID Validation on API Query Parameters]
**Vulnerability:** Several API endpoints (`/api/user/step-calendar`, `/api/user/achievement-progress`, `/api/user/follow/status`, `/api/reactions`) read UUID values from URL query parameters (`userId`, `toUserId`, `targetUserId`) and passed them directly to Supabase client queries without verifying their format.
**Learning:** Passing malformed or invalid UUID strings directly to Supabase/PostgreSQL `.eq('id', malformed_string)` methods does not get sanitized gracefully in all PostgREST queries; it throws an unhandled database exception leading to a 500 Internal Server Error. This can lead to stack trace leakage and Denial of Service (DoS) due to database error exhaustion.
**Prevention:** All API handlers extracting UUIDs from external sources (query string, request body) must strictly validate the string using a Regex (`isValidUUID`) and return a fast 400 Bad Request before attempting to communicate with the database.
