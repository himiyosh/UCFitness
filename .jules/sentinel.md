## 2025-02-14 - Fix IDOR and Unhandled Server Errors Due to Missing UUID Validation
**Vulnerability:** Several API routes (`app/api/user/follow/status`, `app/api/user/step-calendar`, and `app/api/user/achievement-progress`) read `targetUserId` or `userId` from query parameters and directly passed them into Supabase queries (some with `supabaseAdmin`, bypassing RLS) without validation. This caused unhandled 500 errors when invalid UUID strings were provided and exposed an IDOR vulnerability where any user could read another user's private data.
**Learning:** Supabase throws an unhandled 500 exception when parsing an invalid UUID string. Also, when using `supabaseAdmin`, bypassing RLS allows for significant data exposure if inputs aren't cross-referenced against the authenticated user's session.
**Prevention:** Always validate UUID query parameters with `isValidUUID()` before making database calls. Additionally, always check that the requested `userId` matches the session user (`session.user.id`) for endpoints exposing private user data (e.g., `coin_balances`).
