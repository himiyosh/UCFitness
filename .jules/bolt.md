## 2025-05-08 - [Memoizing Deeply Nested Components in Inline List Renderers]
**Learning:** In components rendering lists inline (e.g., `AnimatedLeaderboard` mapping `paginatedItems` directly in JSX) without extracting a distinct row component, parent state changes like mouse hover or long-press will trigger a re-render of the entire mapped list. This makes deeply nested primitive components, such as `UserAvatar`, severely susceptible to unnecessary and expensive re-rendering. Furthermore, even if the primitive is wrapped in `React.memo()`, referential instability of the parent map array (e.g., `paginatedItems` being re-created on every render) can still bottleneck performance or cause hooks exhaustive-deps warnings.
**Action:** When working on lists that lack dedicated row components, always memoize the derived list array (e.g., via `useMemo` for `paginatedItems`) at the top level and ensure deeply nested functional components (like `UserAvatar`) are strictly wrapped in `React.memo()`. Retain the named function structure (`const Component = memo(function Component(...) { ... })`) to aid debugging in React DevTools.
